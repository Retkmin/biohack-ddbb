ANEXO C
MÓDULO DE IDENTIFICACIÓN DE ALIMENTOS
ASISTENTE CONVERSACIONAL CON IA
Versión 1.0
Complemento al Marco Maestro SAM v1.4

1. VISIÓN GENERAL DEL MÓDULO
El módulo de identificación de alimentos permite al usuario registrar sus ingestas mediante conversación natural en texto o imagen, eliminando la fricción del registro manual tradicional. El sistema utiliza modelos de IA para extraer alimentos, cantidades y calcular macros automáticamente.
1.1 Casos de Uso
Entrada por Texto:
Usuario: "Desayuno: 3 huevos revueltos, 100g de avena con leche desnatada, 1 plátano"
Sistema: Identifica alimentos → Calcula macros → Muestra proyección diaria → Alerta proactiva si rompe suelos
Entrada por Imagen:
Usuario: Sube foto del plato
Sistema: Identifica visualmente alimentos → Estima cantidades → Pregunta confirmación → Calcula macros
Conversación Iterativa:
Usuario: "¿Cuánta proteína llevo hoy?"
Sistema: "Llevas 98g de proteína. Te faltan 67g para alcanzar tu objetivo de 165g. Considera añadir: 200g de pechuga de pollo (46g) + 1 batido ISO (26g)."

Ventajas:

3. FLUJO DE INTERACCIÓN
3.1 Registro de Ingesta por Texto
FLUJO DETALLADO:

1. Usuario escribe: "Comida: 200g de pechuga de pollo a la plancha, ensalada con tomate, pepino y aceite de oliva, 150g de arroz basmati"

2. Frontend envía a Backend: POST /api/ai/parse-meal
   - Texto del usuario
   - Contexto del día (macros actuales, slot seleccionado)
   - Perfil del usuario (LBM, fase, suelos)

3. Backend llama a Claude API con prompt estructurado:
   {
     "model": "claude-3-5-sonnet-20241022",
     "max_tokens": 2000,
     "messages": [
       {
         "role": "user",
         "content": "Analiza esta comida y extrae..."
       }
     ]
   }

4. Claude responde con JSON estructurado:
   {
     "foods": [
       {
         "name": "Pechuga de pollo",
         "quantity": 200,
         "unit": "g",
         "protein": 46,
         "fat": 2,
         "carbs": 0,
         "calories": 200
       },
       {...}
     ],
     "totalMacros": {...},
     "confidence": 0.95
   }

5. Backend valida y proyecta macros diarios

6. Frontend muestra:
   - Alimentos detectados (editable)
   - Proyección diaria actualizada
   - Alertas si rompe suelos
   - Botón 'Confirmar' o 'Editar'
3.2 Registro de Ingesta por Imagen
FLUJO DETALLADO:

1. Usuario sube foto del plato

2. Frontend convierte imagen a base64 y envía:
   POST /api/ai/analyze-image
   - Imagen en base64
   - Tipo MIME (image/jpeg)
   - Slot seleccionado

3. Backend llama a Claude Vision API:
   {
     "model": "claude-3-5-sonnet-20241022",
     "max_tokens": 2000,
     "messages": [
       {
         "role": "user",
         "content": [
           {
             "type": "image",
             "source": {
               "type": "base64",
               "media_type": "image/jpeg",
               "data": "<base64_data>"
             }
           },
           {
             "type": "text",
             "text": "Identifica alimentos..."
           }
         ]
       }
     ]
   }

4. Claude responde con estimación:
   {
     "foods": [...],
     "confidence": 0.75,
     "requiresConfirmation": true,
     "uncertainItems": [
       "Cantidad de arroz (estimado ~150g)"
     ]
   }

5. Frontend solicita confirmación al usuario:
   'Detecté 200g de pollo, 150g de arroz (¿correcto?), ensalada.'

6. Usuario ajusta cantidades si es necesario

7. Sistema calcula macros y proyecta
3.3 Conversación Contextual
El sistema mantiene contexto de la sesión para preguntas como:
"¿Cuánta proteína me falta?" → Sistema conoce macros actuales y objetivo
"¿Qué puedo comer para llegar al objetivo?" → Sugiere alimentos según déficit
"Esa cantidad de pollo era más bien 250g" → Actualiza el slot en modo simulación
"¿Rompo algún suelo si ceno esto?" → Proyecta y alerta proactivamente

5. PROMPTS DEL SISTEMA
5.1 System Prompt para Análisis de Texto
Eres un asistente especializado en análisis nutricional para el Sistema de Auditoría Metabólica (SAM).

TAREA:
Analiza el texto del usuario y extrae los alimentos con sus cantidades exactas. Calcula macronutrientes (proteína, grasa, carbohidratos) y calorías usando la base de datos USDA/BEDCA.

REGLAS:
1. Si no se especifica cantidad, usa porciones estándar (ej: 1 huevo = 50g, 1 plátano = 120g)
2. Siempre responde en formato JSON válido
3. Sé conservador con las estimaciones de aceite/grasas añadidas
4. Si hay ambigüedad, pregunta al usuario en el campo 'clarificationNeeded'

FORMATO DE RESPUESTA:
{
  "foods": [
    {
      "name": "Nombre del alimento",
      "quantity": número,
      "unit": "g" | "ml" | "unit",
      "protein": número,
      "fat": número,
      "carbs": número,
      "calories": número
    }
  ],
  "confidence": 0.0 a 1.0,
  "clarificationNeeded": "Pregunta si hay ambigüedad" | null
}
5.2 System Prompt para Análisis de Imagen
Eres un experto en análisis visual de alimentos para nutrición deportiva.

TAREA:
Analiza la imagen y detecta todos los alimentos visibles. Estima cantidades en gramos usando referencias visuales (tamaño del plato, objetos conocidos).

REGLAS:
1. Identifica el tipo de plato (diámetro estándar ~26cm)
2. Usa comparación volumétrica para estimar pesos
3. Indica nivel de confianza bajo si la imagen es borrosa/oscura
4. SIEMPRE marca 'requiresConfirmation: true' para análisis visual
5. Listar alimentos en orden de prominencia visual

ESTIMACIONES CONSERVADORAS:
- Proteínas: Subestimar en 10% si hay duda
- Aceites/salsas: Solo incluir si claramente visibles
- Carbohidratos: Arroz cocido ~150g por taza visual

Mismo formato JSON que análisis de texto.
5.3 System Prompt para Chat Contextual
Eres un coach nutricional especializado en composición corporal y pérdida de grasa.

CONTEXTO DEL USUARIO:
- LBM (masa magra): {{lbm}} kg
- Fase: {{phase}}
- Suelos biológicos: Proteína {{proteinFloor}}g, Grasa {{fatFloor}}g, HC {{carbsFloor}}g
- Macros actuales hoy: Proteína {{currentProtein}}g, Grasa {{currentFat}}g, HC {{currentCarbs}}g

REGLAS:
1. Responde de forma concisa y directa
2. Si preguntan por déficit de macros, calcula exactamente cuánto falta
3. Sugiere alimentos concretos con cantidades específicas
4. NUNCA recomiendes romper los suelos biológicos
5. Si detectas que un suelo está en riesgo, alerta proactivamente

TONO:
Profesional pero cercano. Usa datos numéricos precisos. No uses emojis.

6. CONSIDERACIONES DE SEGURIDAD Y PRIVACIDAD
6.1 Datos Sensibles en Prompts
⚠️ IMPORTANTE: Los prompts enviados a APIs externas (Anthropic/OpenAI) NO deben contener información personal identificable más allá de los datos nutricionales necesarios.
Datos que SÍ se pueden enviar:
LBM (masa magra) en kg - dato agregado
Fase del programa (deficit_a, deficit_b, maintenance)
Suelos biológicos (proteína, grasa, HC en gramos)
Macros acumulados del día (números sin contexto personal)
Datos que NO se deben enviar:
Nombre completo del usuario
Email o teléfono
Dirección o ubicación específica
Condiciones médicas específicas (diabetes, hipertensión, etc.)
6.2 Retención de Datos por el Proveedor
Anthropic Claude API: NO retiene prompts por defecto (Zero Data Retention). Ideal para datos de salud.
OpenAI GPT-4 API: Retiene datos 30 días por defecto. Requiere opt-out explícito para Zero Retention (disponible para clientes Enterprise).
6.3 Cifrado en Tránsito
Todas las llamadas a APIs externas deben usar HTTPS (TLS 1.3)
API Keys almacenadas en variables de entorno (nunca en código)
Rotación de API Keys cada 90 días (automatizado)
